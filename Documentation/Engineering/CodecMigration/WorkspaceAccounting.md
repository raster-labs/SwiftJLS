## 22 October caller-workspace profile and fresh-owned factory

The separate `QualifiedMonochromeDecoder` uses caller-provided fixed payload rather than the owning paths tabulated below. Its source-defined payload is `256 * MemoryLayout<Int>.stride + 65_536 * MemoryLayout<UInt16>.stride + QualifiedContextModel.workspaceByteCount`: palette widths/entries and scalar regular/run contexts. This is 144,864 bytes on the measured 64-bit ABI and 137,968 bytes by the 32-bit layout formula. Input and final UInt16 output remain borrowed; no row or full-frame staging buffer is created. Inspection requires the same reusable scratch but does not decode entropy. The development ordinary-release allocation probe observes selected Linux allocator entry points, with positive controls, cold operations, valid fixtures, rejection and cancellation cases. [The maintenance-fix record](RecentFixes.md) retains measured results and exclusions. ## Units and lifetime

Let `I = MemoryLayout<Int>.stride`, `C` be the admitted component count (1–4), `W` the active component width, `T3` the validated gradient threshold, and `G = (2*T3+1)*I`. `T3 <= 65535`, so a gradient table has at most 131,071 elements. The context payload is `365*4*I`: 11,680 bytes on 64-bit hosts or 5,840 bytes with 32-bit `Int`. Payload sizes below exclude allocation headers, capacity rounding and allocator overhead; the requested-heap ledger includes the first two where Heaptrack observes them.

Only one scan/chunk kernel executes at a time within an operation. Non-interleaved components and restart chunks reuse the operation's compressed writer or final destination sequentially. Their workspaces are not multiplied by the number of scans/chunks. Concurrent callers have separate contexts and row storage; the library's per-operation admission does not establish a process-wide concurrency budget.

| Active path | Algorithm payload and lifetime |
| --- | --- |
| Scalar lossless encode | One context, one gradient table `G`, fixed run/bit state. Reads causal samples directly from the source. No predictor rows. |
| Scalar near-lossless encode | One context, one near-lossless gradient table `G`, and two reconstructed `UInt16` rows (`4*W` bytes). The outer scalar entry creates regular/run state only for lossless coding. The unchanged admission still conservatively allows `2*G`. |
| Component non-interleaved encode | One active context/table; near-lossless adds two rows for the current component (`4*W`). The component views remain borrowed throughout the source access. |
| Line/sample-interleaved lossless encode | One shared context/table, per-component run indices and causal-neighbour scheduling. No reconstructed rows. Line mode uses the scalar row loop; contiguous component layouts use scalar views without copying samples. |
| Line/sample-interleaved near-lossless encode | One shared context/table and two `UInt16` rows per component (`4*W*C`). The array of predictor-row descriptors has `C` entries; it does not contain a full frame. |
| Scalar/component decode, owned or supplied | One active context/table and bit-reader state (one array owner, four integer counters and a 64-bit entropy window). The component path's inlined reader object occupies 64 requested heap bytes on the measured ABI at all recorded checkpoints. Causal samples are read from the final output. No reconstructed-row arrays or second decoded image. Line/sample scheduling retains only bounded component state. |
| HP1/HP2/HP3 encode | Three transformed reader descriptors borrow the existing three source views. Transform arithmetic is performed during reads. No transformed sample frame or row is allocated. |
| HP1/HP2/HP3 decode | Inversion writes directly into the final destination after prediction. Three view descriptors and at most three mapping-table references are retained; no transformed output frame is allocated. |
| Mapping-table application | The parser retains admitted metadata/table entries. Application walks the final destination with bounded checkpoints and scalar temporaries. There is no additional mapped sample frame. |
| Inspection | Header/scan-directory, metadata and output-layout descriptors only. It creates no prediction context, gradient table or pixel owner. |

`JPEGLSContextModel` is noncopyable and owns one `ManagedBuffer` of 365 integer-only records. Every element pointer stays inside a synchronous borrow. Four two-element run-state arrays are inline (`8*I` bytes), eliminating their heap allocations. Component scheduling uses four-element inline arrays: each integer array is `4*I`, and the neighbour array is `16*I`. Their storage belongs to the containing stack/value; it is not counted again as heap. They have fixed bounds regardless of image dimensions.

Interleaved decode also retains one heap-backed vertical-sampling schedule for the active scan, with `C*I` integer payload (`C <= 4`), separate from those inline arrays. The caller constructs it from the admitted component sampling factors; the kernel uses the same array storage without mutation. It is algorithm-state scheduling storage, not metadata or pixels, and its observed array header/capacity is included in the algorithm-state requested-heap category.

`ComponentSampleReader` and `ComponentSampleWriter` contain a raw-buffer view, six integers and two layout flags; descriptor-array payload is `C*MemoryLayout<View>.stride` (72 bytes per view on the measured 64-bit ABI). Predictor-row descriptors contain two array owners and two edge integers. These descriptors retain their owners only for synchronous codec access. HP reader descriptors retain the already-created source-view array by value without mutating it. Their small payload, allocation headers and helper state fit within the existing conservative 64 KiB context/state allowance; that allowance is not a measurement.

The regular/run objects, scalar neighbours, counters, 64-bit entropy windows, SIMD run/precision comparisons and transform arithmetic are fixed-size locals. The two run-code J tables each contain 32 immutable integers. They are process-wide constants rather than per-frame mutable workspace; their image/first-use runtime storage is not charged repeatedly as a new frame allocation. Inherited allocating helpers such as `reconstructRunPixels`, `splitRunLength` and array-based line convenience methods are not called by the public codec kernels. The public entry paths use the scoped views listed above.

The MAXVAL validators are concrete generic values: `JPEGLSPrevalidatedSamples` has no stored fields, and `JPEGLSMaximumSample` stores one `Int`. They retain no sample owner or scratch array. Lossless precision checks are folded into coding; near-lossless and HP inputs retain their bounded prepass. Contiguous component-to-scalar adapters rebase the existing borrowed buffer before constructing coding state; the near-lossless adapter returns after that delegated call, so it does not retain another context, gradient table or pair of rows. Checked address proofs and removal of duplicate column-zero polls add no source-level storage.

The native-endian 16-bit adapters are fixed-size borrowed values containing a raw base pointer, sample count and the original scalar view. They are selected inside the existing synchronous owner borrow, use unaligned loads/stores, and allocate no sample buffer, context or predictor row. Bulk access delegates to the original bounded view. Their observed heap effects are included in the refreshed matrix; this source inventory does not infer their exact stack placement. Combining the quantized context index and sign arithmetically changes only fixed scalar temporaries; it adds no retained state or storage owner.

Sample-interleaved decode additionally selects native writers once for packed, full-resolution UInt16 planes in native byte order; padded, sparse, byte-sized and opposite-endian destinations retain the general view. The [selection at `e6a6436`](https://github.com/raster-labs/SwiftJLS/blob/e6a6436c692f5af226bffceb70b7ee65c774edf3/Sources/SwiftJLS/JPEGLS/InterleavedKernel.swift#L238) constructs at most four borrowed `NativeUInt16Writer` values within the existing synchronous owner borrow. Their logical payload is `C*MemoryLayout<NativeUInt16Writer>.stride`; the measured 64-bit ABI has a 48-byte stride. Array growth/header costs are measured separately below. The original component-view array remains alive; no sample frame, predictor row or context is added. The descriptor growth fits the existing conservative 64 KiB allowance; that allowance remains an admission bound, not a measured peak.

The header retains one immutable, admitted default `ImageDescriptor`; `roles` returns its component array and successful `descriptor(limits:)` validation returns the shared value. Rejected descriptor requests rebuild the original diagnostic path. This avoids duplicate descriptor containers for owned decode, while supplied-destination decode may retain the default descriptor's containers through the operation. Those arrays remain metadata/control storage rather than algorithm or pixel storage. `ImageDestination` adds one finished Boolean to its existing mutex-protected lifecycle value, with no new state object; completed success or abort avoids redundant cleanup, while failed aborts remain retryable. These changes do not change the algorithm payload formulas; their measured allocation effects remain in their separate categories.

Successful canonical frame admission at SOF, extended dimensions and SOS now uses checked fixed-size arithmetic instead of constructing a discarded greyscale descriptor. Rejected cases invoke the original descriptor constructor to preserve error/check order. The final interpreted descriptor is still constructed and admitted at EOI, and existing component, metadata and memory limits remain in force. This removes temporary descriptor containers rather than algorithm or pixel buffers.

Descriptor validation omits a uniqueness `Set` for a singleton plane component list, traverses sampling maxima lazily instead of constructing arrays, and does not retain an overlap range when there is only one plane. The image-component mapping also bypasses its `Set` only for exactly one image component, one plane and one plane component; the existing range check still runs first. Every other mapping shape retains the original set validation. Multi-plane overlap checks, checked arithmetic and rejection order remain unchanged. These are temporary metadata/descriptor allocation reductions. Reusing an existing row-entry checkpoint for its first bounded lossless run scan or short run fill adds no storage or retained state.

The parser tracks completed frame components in one `UInt8` mask: frame admission bounds every shift to indices 0–3. A bounded scan of the admitted sampling values replaces a temporary sampling set. Metadata validation checks each required key directly in the existing dictionary instead of constructing a set of all entry keys. These changes remove temporary metadata/control containers; they add no sample storage or algorithm array.

Owned destination allocation performs the original descriptor and combined-memory admission, constructs the same exact-capacity `OwnedImageStorage`, then uses a private initializer that reserves the same write lease. It omits repeated immutable descriptor/capacity checks without adding a state object. The public provider initializer, owned-storage cancellation check, lease and publication lifecycle remain unchanged.

Decoder gradient-table construction initialises the same `2*T3+1` integer payload with adjacent constant interval fills when `NEAR < T1`. The source fallback retains the original branch calculation for the internal `NEAR >= T1` case. Both paths own one table `G`; the scoped buffer and index temporaries add no heap owner. The ordinary-release algorithm-state peaks below are unchanged from `bee49a2`; exact stack placement remains unmeasured.

Scalar near-lossless row reconstruction now takes one synchronous mutable borrow of `current` per row and ends it before swapping `current` and `previous`. Neither row is resized or published during the borrow, and no third row or frame owner is introduced. For the maximum-table `W=257` profile on a 64-bit host, the current context/table/row payload is `11,680 + 1,048,568 + 1,028 = 1,061,276` bytes, excluding descriptors, headers and other fixed state. This is a source-level payload calculation. The corresponding observed algorithm-state requested-heap peak is 1,061,388 bytes; it is not a combined stack/heap measurement.

## Other storage that must remain separate

| Storage | Bound/accounting boundary |
| --- | --- |
| Source and supplied destination | Caller-owned live baseline. They are not new algorithm allocations. Supplied decode must add zero owned pixel buffers and preserve allocation identity. |
| Owned decode result | Exactly one final storage owner of the admitted descriptor capacity. Its lifetime continues beyond the operation. It is pixel storage, not workspace. |
| Encode compressed writer/result | The writer enforces `maximumCompressedBytes` on every append. Admission reserves two output-limit payloads for growth/final `Data` coexistence, separately from the source. Requested capacity/header bytes remain in the compressed category. |
| Decode compressed input/reader | Input remains live. The active scan reader copies compressed bytes into its byte array; it does not copy samples. Admission allows two input-sized payloads in addition to the retained compressed input. Scan ranges are processed sequentially. |
| Scan directories | Parser admission bounds range storage using the validated restart schedule and checked arithmetic. Decode admits the total range-directory allowance. Component/selector/layout arrays have admitted component counts. |
| Metadata/mapping/SPIFF/extended dimensions | Admitted metadata bytes and parser/descriptor containers have their own category. The existing memory admission includes the conservative metadata multiplier. Retained metadata is output/control information, not prediction state. |
| Closures, leases and storage objects | Separately attributed control allocations. Historical measurements include cleanup errors from invalidating an already-finished write lease; the current lifecycle avoids that redundant cleanup. Remaining error objects are neither pixel buffers nor context records. |
| Swift/Foundation runtime | Type metadata, key paths, executor/thread and other runtime allocations remain separate. Unknown runtime attribution is retained explicitly. |

The production resource limits and admission formulas are unchanged. They include context allowance, gradient construction, predictor rows where needed, compressed storage and metadata/directory bounds. Oversized dimensions, strides, coding parameters and byte counts still fail admission before kernel access. SIMD comparisons examine at most 256 samples per call, stay within one row, and preserve odd-address, byte-order and padding handling. The entropy-directory word scan skips only words containing no `FF`; candidate words retain byte-by-byte stuffing/marker validation and bounded deadline checks.

The literal-array rules describe the observed Swift 6.4 x86_64 allocation shape (32-byte array header plus the stated payload). They deliberately leave a different size, missing size, intervening allocation frame or different ABI unattributed rather than extrapolating from the caller name. Negative controls exercise those exclusions, the bit-reader size boundary, a megabyte-sized integer array, and a codec stack that merely mentions the bit writer. Separate controls keep Swift type-metadata caches and Foundation's named `ProcessInfo`/cgroup-URL singleton allocations in the runtime category even when codec setup triggers their first use. The completeness control also rejects unknown codec storage already live at the begin marker. The event-replay controls reject missing/repeated markers and unmatched frees. The source bounds above cover supported algorithm paths; the finite matrix does not prove every possible input, error path, allocator or concurrent-call schedule.

Massif stack observations include runtime threads and marker activity. They do not establish an exact codec-only transient stack peak, and modelled heap overhead is not allocator usable size. The source inventory above accounts for the algorithm's fixed and row-dependent storage; actual compiler spills, async/runtime frames, allocator overhead and an exact universal per-operation total remain unknown. Accordingly, production `peakWorkspaceBytes` stays `nil`. This honours MEM-12's requirement to distinguish measurable workspace from unknown measurements; it does not substitute requested heap or RSS for pure algorithm workspace.
