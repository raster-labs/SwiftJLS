## Multi-component checkpoint

## HP reversible RGB checkpoint

Original Swift scalar lifting code adds the private APP8 `mrfx` HP1/HP2/HP3 convention. Encoding reads transformed values directly from the sealed RGB owner through three tiny component views. Interleaved entropy coding retains its bounded predictor rows. Decoding first reconstructs into the final caller allocation, then inverses the transform in place before sealing. The inverse pass checks cancellation/deadlines every 64 pixels. No transformed frame is allocated or copied. Ordinary allocator telemetry is still required to qualify that source-level observation.

The supported profile is lossless, full-range 8/16 meaningful bits, three RGB components, line/sample interleaving. Encoder presets are rejected; the decoder accepts full-range explicit thresholds such as CharLS's 16-bit marker. Rejected profiles include transformed near-lossless (the RGB error bound would not follow from transformed-channel NEAR), reduced MAXVAL, other precisions and non-interleaved transforms. Duplicate/late/unknown markers, combined metadata budgets and rejection before destination write are tested. The marker itself supplies RGB interpretation when SPIFF is absent.

36 new synthetic fixtures cover all three transforms, both precisions and interleave modes, noise, flat runs and one-column edges. Every sample is checked across planar/pixel layouts, reversed physical channel order, both byte orders, padding and different destination strides. CharLS 2.4.2 independently decoded all 366 component successor streams, including the 36 transform streams, with the declared fidelity. The full 60-declaration debug, release, AddressSanitizer and ThreadSanitizer runs passed; results are `hp-*.json`. No external implementation or runtime dependency is introduced.

Predecessor `15aa75164145414f3d5ffb801401c52d40cc5bcc` uses different transform formulae under the same marker: HP1/HP2 have no half-range bias and HP3 is a different transform. These legacy streams cannot be autodetected safely. `MIGRATION.md` documents the explicit legacy-decoder route; source-level compatibility is not reported as wire compatibility. The transform convention is tested against the pinned independent oracle, not described as normative T.870. Older fuzz and benchmark results apply to their recorded pre-transform sources; transform-duration fuzz and performance qualification are separate outstanding gates.
