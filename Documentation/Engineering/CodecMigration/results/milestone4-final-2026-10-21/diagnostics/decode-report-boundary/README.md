# Decode report-boundary and identity-cost diagnostics

Production remains `bee49a2ad47eae4ea149bdced2043b7a45df3dae`. This package links the unchanged successor source, uses explicit CLT Swift 6.4 release compilation, and changes only a copied Consumer. It does not weaken the public `@concurrent` executor policy, cancellation, deadline, capacity or resource checks.

The original Consumer discards `DecodedImage.report.elapsedSeconds`. The diagnostic returns that existing value from its decode helper as a `Double`, preserving image destruction inside the helper and the outer call timer. Report and zero controls use one compiled binary and the identical timed path/return ABI: a runtime environment flag masks only the recorded value after the outer timer ends. This controls process variability; it does not remove the cost of reading/returning the report, so the changed ABI and code layout remain limitations. The initial two-binary build is retained under `initial-two-binary-build/` and was never timed.

The internal report starts at `CodecBudget` creation before header parsing and includes header/admission/allocation/kernel/seal work through report construction. It excludes executor entry/return, early public admission, final progress/checks and some destruction. Therefore outer minus reported duration must not be described as pure executor cost. First establish that report-mode outer timing reproduces the observed short-versus-long direction, then inspect which interval changes. This is localisation evidence, not a cause or performance acceptance.

`schedule.json` SHA-256 is `de33e16172504642f346e19fa2061c546b8bcddf9ad0ffcab61e2dbc0915abe2`. The predeclared decode schedule has 16 blocks of 37×23 flat 12/16-bit inputs, each in short5/5 and long20,000/1,000 modes, with balanced report/zero process order and alternating mode/case order. All four original operation timings and every reported decode observation are retained. There are 128 decode processes. The separate identity microdiagnostic has 96 processes: 16 blocks ×two warmup modes ×three constructors, with rotated/reversed constructor order. No reruns or result-dependent exclusions are automatic.

The microdiagnostic measures preserved calls that construct, consume and destroy either `UUID()`, an empty immutable reference identity, or host-only `UUID.random(using: SystemRandomNumberGenerator())`. Disassembly records an actual reference `swift_allocObject` and `swift_release`, Foundation UUID construction, and the random-UUID call. Clock, dispatch and consumption costs are included; these are not isolated allocation-only measurements. The reference identity is forbidden as a production lease replacement by the immutable UUID requirement in `MEMORY_CONTRACT.md:105`. The random factory requires OS26.4 and cannot be used unconditionally for this library's OS26.0 floor. Neither microcomparison authorises a contract change or custom RNG implementation.

`build.json`, `consumer.patch`, source files, `report-public-boundary.txt` and `micro-preserved-boundaries.txt` preserve provenance. The public decoder call survived compilation. `preflight-correctness-only/` retains sample-verifying codec invocations and availability checks; their timings are not comparative evidence. The runner checks AC, exact production source, frozen primary binary identities and diagnostic binary hashes; captures AC/thermal/load; and retains partial outputs on interruption. Admission attempts in `results-1` and `results-2` stopped on battery before any measured process. They remain retained, and a fresh directory is required for the eventual powered run.

Powered `results-3` completed all128 decode and96 micro processes. Its initial micro validator rejected zero elapsed values from the sub-tick reference allocation; those observations were valid clock-resolution zeros. The fifth process was recovered unchanged from `interrupted.json`, and `resume-micro.py` ran only the91 previously unstarted entries. No process was repeated, no observation dropped and no epsilon substituted. The complete logical micro data is `results-3/micro-raw-complete.jsonl`; the original partial file and interruption remain. `validator-correction.json` records the original and continuation runner hashes. Micro ratios with a zero denominator would be undefined; this analysis reports absolute micro durations only. `RESULTS.md` and `results-3/analysis.json` record the completed measurements and limitations.

For future reproduction, `run.py` now accepts finite nonnegative micro durations from the outset. The exact initially executed source is retained as `run-before-zero-correction.py`; before/after hashes and the distinct continuation hash are in the correction record. The corrected runner was not used to produce or alter retained timing observations.
