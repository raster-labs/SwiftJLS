# Lifecycle and Int8 candidate source review

**Accepted at the four-file identities in `002-lifecycle-int8-review.json`; no actionable correctness finding.** This is source acceptance pending root's builds/tests and performance qualification. Read-only: no source edits, builds or measurements; the concurrent parser/helper work was excluded.

The new atomic state has the same observable state machine as the prior mutex flags. Metadata/combined-budget rejection still occurs before claiming a write, so admission rejection remains retryable. Strong compare-exchange from ready to writing admits at most one caller; there is no reset/ABA path. Success stores finished after the existing final cancellation check. Failed fill/validation/sealing attempts abort, and finished is stored only when abort succeeds; failed abort remains writing for deinit retry. Acquire/release ordering protects these monotonic lifecycle observations. The immutable owned-admission flag is initialised before publication. Provider reservation/borrows/sealing, storage CAS/mutex and UUID leases remain unchanged.

Both private gradient arrays now contain Int8, while thresholds, counts, offsets, indexes and all returned quantizer results remain Int. Every stored literal/reference return is within -4...4; the decoder's private reference now returns Int8 directly, avoiding any truncating conversion. Encoder near-first and decoder threshold-first fallback precedence remain separate. Outer Int.min/max clamps and every interval extent are unchanged. Existing conservative tableBytes admission is untouched, so this representation change does not broaden resource-limit acceptance.

The new DispatchQueue.concurrentPerform test runs 32 repeated groups of 32 writes against one allocated destination, checks one entered fill and one image, rejects every non-already-used error, and preserves allocation identity. It meaningfully exercises concurrent single-use claims. Existing DestinationLifecycleTests independently covers abort counts, release retry and cancellation during seal; OwnedAdmissionTests covers rejection/retry ordering. The existing independent GradientTableTests exhaust signed outputs, maximum table extent, equal thresholds and fallback cases. No implementation-mirroring table oracle was introduced.

Test limitation: concurrentPerform is a stress schedule, not a deterministic guarantee that a losing write runs while the winner is inside its fill. Its zero fill also matches the initial zeroed storage. Neither is a blocker given the existing lifecycle/fidelity tests; a nonzero byte pattern would strengthen this new publication assertion without adding another test. No runtime or latency claim is inferred from this review.
