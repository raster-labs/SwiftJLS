# Independent JPEG-LS oracle

The Swift package does not fetch or link CharLS. Build this development-only adapter against a separate CharLS checkout at `36dd3307e070d8fbc765c3ba890b7e681046fa39` (2.4.2, BSD-3-Clause). Keep its licence with that external checkout. This directory's adapter, scripts and synthetic fixtures are Apache-2.0.

From the repository, substituting absolute external paths:

```sh
clang++ -std=c++17 -O2 -DNDEBUG -DCHARLS_STATIC -DCHARLS_LIBRARY_BUILD \
  -I/path/to/charls/include -I/path/to/charls/src \
  /path/to/charls/src/*.cpp Scripts/Interop/charls-driver.cpp -o /path/to/oracle
python3 Scripts/Interop/generate-fixtures.py --oracle /path/to/oracle --output /path/to/fixtures
python3 Scripts/Interop/generate-near-fixtures.py --oracle /path/to/oracle --output /path/to/fixtures
```

The checked-in manifest pins every codestream and sample hash. Regeneration is a deliberate fixture change. Swift tests read these resources without invoking an external codec.

Compile `Consumer.swift` in an independent executable package depending only on this `SwiftJLS` library, then run its binary with the absolute fixture and output directories as arguments. It encodes original samples, preserving every fixture's precision and NEAR. Verify the outputs with:

```sh
python3 Scripts/Interop/verify.py --oracle /path/to/oracle \
  --fixtures /path/to/fixtures --encoded /path/to/consumer-output \
  --report /path/to/new-report.json
```

Each result must have the specified dimensions, precision and NEAR, and every logical sample must satisfy the bound. The package's tests also decode independent input and compare the exact oracle reconstruction. Self-roundtrips alone are not the compatibility evidence.

Restart fixtures are generated by `generate-restart-fixtures.py` from independently encoded CharLS row groups, then the complete DRI/RST stream is decoded by CharLS before acceptance. Both fidelity modes are covered.

For arbitrary MAXVAL presets use the isolated published T.87 reference workflow, not CharLS 2.4.2. Download its `reference-results` artifact and import it with:

```sh
python3 Scripts/Interop/generate-preset-fixtures.py \
  --candidates Scripts/Interop/reference-candidates.json \
  --report /path/to/reference-results.json --output /path/to/fixtures
```

Use `verify.py --exclude-presets` for the CharLS portion and record the published-reference gate separately. An excluded case is not an independent pass. The six MAXVAL 1/2 candidates are outside the published reference's supported alphabet range; the manifest retains this coverage gap. Reference software is downloaded only for conformance tests, retains its original licence, and is never included in SwiftJLS.

## Component interop

Append `ComponentConsumer.swift` to `Consumer.swift` in the independent consumer package to export component outputs and non-interleaved restart variants. Run `verify-components.py` with the same four path arguments as `verify.py`. It verifies every checked-in component fixture hash and independently checks geometry, precision, NEAR and every logical sample in 330 successor outputs. Regenerate fixtures with `generate-component-fixtures.py --oracle ORACLE --output FIXTURES --interleave MODE` for each of 0, 1 and 2. Canonical `.u16le` samples are planar regardless of codestream interleaving.

`components.json` records 231 cases. CharLS 2.4.2 cannot decode two-component interleaving; those profiles have separately named local invariant tests, not independent conformance passes. The interop workflow builds the pinned BSD-3-Clause oracle in `/tmp` and retains its checkout/licence there for the job; the Swift library has no oracle dependency.

`TwoComponentConsumer.swift` exports 33 two-component line candidates with explicit normative presets. The published reference workflow validates both directions through separate PGM planes. Import a fully passing result with `generate-reference-components.py --candidates CANDIDATES --report REPORT --output FIXTURES`. The native tests consume `components-reference.json` alongside the CharLS component manifest. Explicit presets avoid the HP V1.00 implicit-default discrepancy observed at MAXVAL=3, NEAR=1; this is recorded as an oracle interoperability limitation, not hidden by changing the native default formula. See the standalone CharLS `low-max-near-default` regression and the original diagnostic workflow 38036646088.

`generate-hp-fixtures.py --oracle PATH --output Tests/SwiftJLSTests/Fixtures --transform 1` (repeat 2 and 3) generates the private HP convention's 36 lossless RGB cases. `ComponentConsumer.swift` and `verify-components.py` include `components-hp.json`, so both independent directions are reproduced by CI. Full-range 8/16-bit line/sample modes only; the predecessor's incompatible transform equations are not reused.

`LegacyHPConsumer.swift` runs only against pinned JLSwift to reproduce six diagnostic legacy files and verify its own reconstruction. `LegacyMigrationConsumer.swift` explicitly opts into `hpInterpretation: .legacyJLSwift`, decodes those files and produces standard HP output; `verify-components.py` checks the migrated output with CharLS. Legacy streams are never counted as independently conformant standard HP inputs.
